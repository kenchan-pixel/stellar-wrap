# 設計決定紀錄

本文件只記錄已批准或已成為穩定基線的決定。候選構想放在 [ROADMAP.md](ROADMAP.md)，不得混作已批准功能。

## 狀態定義

- **候選方案：** 尚未驗證，只供研究
- **暫定推薦：** 方向合理，但仍需實作／實機證據
- **已通過驗證：** 技術或體驗測試已通過
- **用戶已批准決定：** 可作後續 SOT，不應無理由重開

---

## D-001｜手機優先的沉浸式星際旅行

- **狀態：用戶已批准決定**
- 主平台為手機直向。
- 主畫面留給星空、轉向、曲速與天文景觀。
- 控制面板可收起；提示集中畫面邊緣。
- 桌面版只作兼容及開發，不可反過來限制手機操作。

## D-002｜後續要求一律累積，不可功能倒退

- **狀態：用戶已批准決定**
- 最新要求是疊加修正，不是只保留最後一項。
- 重構前須列出現有功能清單及回歸測試。
- `releases/v4.0-stable.html` 永遠不覆寫。

## D-003｜以 3D 座標作真實方向來源

- **狀態：用戶已批准決定／已通過驗證**
- 每站具固定 `X / Y / Z` 模擬座標。
- 轉向動畫、中途續航方向、AZ／EL 及星圖箭頭均由同一座標計算。
- 不接受預製左轉／右轉動畫取代實際方向。

## D-004｜單段 6.0 LY、最短距離多段路線

- **狀態：用戶已批准決定／已通過驗證**
- 兩站距離不超過 6.0 LY 才可直航。
- 路線使用 Dijkstra 計算總距離最短路徑。
- 網絡必須保持八站全部互通。

## D-005｜航行時間與距離相關

- **狀態：用戶已批准決定／已通過驗證**
- 曲速巡航時間按航段距離增加。
- 使用者可調 0.7×–1.8× 曲速倍率。
- 畫質調節不可改變航行時間。

## D-006｜完整曲速旅程不可省略

- **狀態：用戶已批准決定**
- 每段必須包括：方向轉向、亞光速加速、曲速進入、巡航、脫離、連續減速、接近及觀景。
- 進入曲速需有星線爆發、隧道、光暈及視角變化。
- 不可因加入真 3D 景觀而刪減曲速效果。

## D-007｜抵達使用連續位置與速度軌跡

- **狀態：用戶已批准決定／已通過驗證**
- `warpExit`、`decelerate`、`approach` 共用 arrival clock。
- 減速後保持低速向前，再於停點煞停。
- UI 階段轉換不得重設場景位置或速度。

## D-008｜每站必須具有獨立 3D 天文地標

- **狀態：用戶已批准決定**
- 到站慢速畫面必須符合目的地設定。
- 地球近軌需有仿真地球、雲、大氣、城市夜光及月球。
- 新增星區不能只換背景色或粒子顏色。

## D-009｜中途站先飛掠，再按下一段重新轉向

- **狀態：用戶已批准決定／已通過驗證**
- 到達中途站時展示當地景觀。
- 下一段開始前，依實際下一站方向平滑轉向。
- 上一站景觀應自然掠出視野，不可突然消失或鏡頭瞬移。

## D-010｜60 Hz 流暢度優先

- **狀態：用戶已批准決定**
- 目標為 60 Hz 裝置上的順暢動畫。
- 負載過高時先降低 DPR、星數、曲速線、隧道環及次要細節。
- 航行節奏、方向及核心地標保留。
- 實際 60 fps 必須由目標手機人手量度，不能只靠程式宣稱。

## D-011｜動態聲音、到站探索、效能層及 2.5D 星圖納入 V4

- **狀態：用戶已批准決定／已通過結構驗證**
- 聲音只在首次使用者互動後啟動。
- 中途站短暫飛掠，最終站進入可拖動探索。
- 星圖顯示路線、方向、距離、時間與航行進度。
- 畫質模式及診斷 HUD 保留。

## D-012｜現階段維持零後端靜態架構

- **狀態：暫定推薦／V4 現況**
- 不加入帳戶、資料庫、分析追蹤或秘密。
- Three.js 以固定 CDN 版本載入。
- 下一步可研究 PWA／離線依賴，但不得先引入大型框架。

## D-013｜Repository 初始策略

- **狀態：暫定推薦**
- 建議 repo：`kenchan-pixel/stellar-wrap`
- 建議先設為 private，待授權、資產及產品方向確認後才決定是否公開。
- `main` 只保留穩定可運行版本；功能透過 branch／PR。
- 專案未授予開源授權。

## D-014｜V4.1.0 成為目前 release baseline

- **狀態：用戶已批准 release baseline／已通過實機驗證**
- 2026-08-27，owner 完成實機 manual test 後合併 PR #4。
- V4.1.0 runtime baseline commit 為 `e852096e65194543b97355efc48894339d550be7`；完整 release 紀錄見 `releases/v4.1.0.md`。
- 本版納入 WebGL context recovery、旅行日誌與距離連續性、LUNA 三點觀測、目的地攝影模式、離線重新啟動／啟動恢復、靜態導航 fallback 及 Arrival Debrief。
- V4.0 `releases/v4.0-stable.html` 仍為不可覆寫的回歸快照，不因 V4.1.0 發佈而修改。
- 這項決定只確認 V4.1.0 已出貨行為成為目前產品基線；不等同批准更廣泛或尚未實作的 V5 roadmap。

## D-015｜Frontier Fiction 改用固定景觀並收斂至一致介面

- **狀態：用戶已批准決定**
- Frontier Fiction 不再以「可自由旋轉的 3D 模型展示」作主要到站體驗；每個目的地應採用策展好的單一英雄景觀／固定構圖，與 Real Space 的觀景語言靠攏。
- Landing Page、目的地選擇、到站控制及留影入口應使用一致的產品層級與操作語言，避免每個科幻目的地自成一套介面。
- 科幻目的地入口不得再以三張小卡加一張 Featured、或隱性把 Frontier 主入口當作某一指定目的地；四站應以同一層級呈現，降低 pointer／焦點混亂。
- 現有 AURELIA／NADIR／VESPER／EIDOLON 3D 場景可繼續作渲染底層，但玩家入口應鎖定經批准的固定構圖；自由拖動、auto-orbit、構圖 preset 不再是主要產品控制。
- 這項改變只適用於 Frontier Fiction。Real Space V4.1 已批准的自由到站探索、相機拖動、航線權威及八站內容不可因此倒退。
- Frontier 航線後續應重用 Real Space 的「選站 → 航程 → 抵達 → 景觀」心智模型，但在建立真實 Frontier route authority 前，不得以 UI 假裝已存在 Dijkstra／距離／物理航線資料。
